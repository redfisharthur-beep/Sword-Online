# 原始資源優先：忠實復刻準則

**此專案目標是忠實還原原始《軒轅劍網路版》的玩法、職業、怪物、地圖、介面及動作，只提高解析度與渲染品質。**
不能把目前以程序生成房屋和方塊人物組成的 world3d.js 當成原版場景；它僅是技術驗證，待解碼完成後必須替換，不能以自創場景繼續擴充。

## 實際查驗的檔案（2026-10-21）
- MODEL.zip：6,173 個 ZIP 項目；MODEL/CHR00001.PLY 為 112,115 bytes，前兩個小端整數分別是 202,484（推定解包大小）和 112,107（等於檔案長度減 8）；並非 Stanford PLY。
- TEX.zip：7,613 個 ZIP 項目；TEX/ALL00000.TEX 為 26,521 bytes，前兩個整數 132,622 與 26,513；TEX/ALL00001.TEX 為 436,178 bytes，前兩個整數 963,610 與 436,170。這是封裝／壓縮線索，**並未確定壓縮演算法**。
- MODEL/MAP00001.WLD：前四個位元組是 `WLD\0`，共 2,501,948 bytes。
- Build/00across01mk.S3D：前四個位元組是 `SS3D`，共 9,728 bytes。
- MODEL/ALL_CHAR.IDX：以 `IDX_PLY\0` 開頭。
- TEX 壓縮檔同時包含 Sound/snd00001.wav（RIFF/WAVE，8,928 bytes）等真正可讀取的原版音效。

這些是真實的檔頭觀察；不代表已解碼骨架、貼圖、地形、材質索引或動畫。

## 可重現的查驗方式

```sh
python3 scripts/inspect_original_assets.py /path/to/MODEL.zip /path/to/TEX.zip --out original-audit
```

會產生兩份 CSV 與 summary.json，不修改來源檔案，也不把未解碼資料誤認為可渲染的模型。

## 後續不可跳過的關卡

1. 找出 PLY / TEX 專用解壓演算法，驗證解壓後長度及資料完整性。
2. 從 IDX 確認角色／物件／貼圖的對應關係。
3. 解析 PLY 頂點、面、UV、骨架與 ACT 動作；輸出 glTF / GLB。
4. 解析 TEX 像素、尺寸、透明度；輸出 PNG / KTX2。
5. 解析 WLD / S3D 的場景物件位置、地形與碰撞；逐地圖重建。
6. 保留原版的視角、動作時序、技能效果與 UI 位置；提高抗鋸齒、材質濾波及輸出解析度。
7. 每一步以原版截圖／影片及轉換資源比對驗收；不能以自創模型充數。

## 目前實作限制
現有 Three.js 3D 場景仍為**佔位模型**，尚未符合原版高度復刻；此提交只建立可檢查的原始資源調查流程，沒有虛稱已轉出任何 GLB。
